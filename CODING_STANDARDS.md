# Coding Standards

Review-stage standards for BPMute. Mechanical checks live in `./scripts/check.sh`, `clippy.toml`, and `Cargo.toml`; run `./scripts/check.sh` rather than auditing them manually.

## Judgement Rules

- **State-transition completeness**: When exiting an active phase (e.g., `Candidate`, `Confirmed`, `Signal Lost`, or stream-mode switch) or executing a destructive/bulk IPC state reset (e.g., `data.hard_wipe`, `data.import`), synchronize every affected actor (`DaemonCore`, `MonitoringContext`, active `GraceCoordinator`) in one dedicated helper, derive updated in-memory `CalibrationState` from `recompute_and_persist_in_tx` rather than synthesizing defaults, and snapshot historical milestone values at the transition. Conversely, when aborting or resetting an unconfirmed phase back to `Monitoring` (e.g., `return_to_monitoring` with `clear_onset_marks = true`), clear all transient phase accumulators and candidate snapshots (`pre_candidate_*`) so stale markers never leak into subsequent sessions. Non-session phases (`Idle`, `Standby`) must never emit `SessionStarted`, `SessionEnded`, or `EpochEmitted`; continuous raw packet filtering computes rolling telemetry (`HrSample`), but discrete epoch events belong exclusively to an open `Monitoring Session`. When executing clock- or deadline-driven session expirations (`ActiveHoursExpired`, schedule boundaries), states with detected or confirmed sleep (`Confirmed`, `Sleeping`) must remain protected across the boundary until physiological or desktop wakefulness resolves closure; only unconfirmed waking phases (`Monitoring`, `Warmup`, `Candidate`) are subject to boundary expiration.
- **Pre-power-action persistence & shutdown control drain**: Before invoking a destructive host power action (`Suspend`, `Poweroff`), deliver `GraceOutcome(Expired)` and persist `sleeping_ts_ms` and `trigger_power_action` to SQLite with a WAL flush (reverting `trigger_power_action` to `PowerAction::None` if the pipeline aborts or `logind` refuses/fails the action); on daemon shutdown, drain queued `EngineControlEvent` messages from `ctrl_rx` before `flush_close_latest`.
- **No speculative unused API surface**: Do not add unused struct fields, enum variants, or constants ahead of their ticket unless required by a persisted schema or wire contract. Avoid re-exporting internal module functions or structs as public crate API at root boundaries (`src/lib.rs`, `src/*/mod.rs`) unless explicitly required by an external consumer.

- **Biometric redaction completeness**: Every `tracing` backend (including `tracing-journald`) and both span attributes/records and events must pass through the shared redaction path so raw BPM/RR telemetry and full MAC addresses never appear unless `--log-biometrics` / `BPMUTE_LOG_BIOMETRICS=1` is active. Redaction helpers (`mask_mac`, text scrubbing) must be idempotent so nested layers never corrupt already-masked values.
- **Boundary trait preservation**: Injected environment, clock, and OS-edge boundaries (`EnvSource`, `DaemonClock`, `WearableSource`, `IdleProbe`, `ActionExecutor`, `Notifier`) must be propagated through spawned tasks and live-reload paths (`SIGHUP`, `config.reload`). Never fall back to concrete `ProcessEnv` or wall-clock globals inside injected paths.
- **Minimal path resolution per CLI subcommand**: Offline and host-boundary subcommands (`completions`, `update`, `service`) must resolve only the directories they genuinely read or write rather than failing eagerly through full `ResolvedPaths::resolve` when unrelated environment variables (e.g., `XDG_DATA_HOME`, `HOME`) are unset.
- **Semantic CLI exit codes (`0`–`5`)**: Map `PermissionDenied` and OS/D-Bus backend refusals consistently to `ExitCode::PermissionOrBackendRefusal` (`5`), offline daemon/unreachable socket to `3`, CLI/config/input validation errors to `2`, precondition/state conflicts to `4`, and generic runtime errors to `1`.
- **Runtime state vs. config reloads**: Unrelated `config.update` or `config.reload` operations must not clobber explicit runtime overrides (such as `monitor.set_dry_run`) unless the reloaded setting itself changed.
- **Worker and spawned async task lifecycle**: Workers (`bpmute-ledger`) and spawned async tasks sharing cloned channels or `Arc` state must terminate via explicit shutdown messages or cooperative cancellation flags, and clear shared pending-waiter maps on exit or EOF so sibling handles never hang waiting on orphaned oneshot receivers.
- **Virtual-time-safe daemon timers**: Arm `select!` countdown or timeout futures in daemon loops only while actively inside a timed phase (e.g., an active gap or `Grace Period`), keeping healthy streaming and `Idle` states on `future::pending()`, so `VirtualClock` tests awaiting real sockets or OS threads never auto-advance prematurely.
- **Module cohesion**: Keep sibling submodules focused on a single responsibility (e.g., `src/cli/commands/`, `src/storage/store/`, `src/daemon/state/`, `src/sleep_engine/state_machine/`) rather than appending unrelated branches to existing files approaching `900+` lines.
- **Shared wire identifiers**: Define IPC identifiers shared between daemon and clients (`alert.id`, error codes, sentinel session IDs) once as constants in `src/ipc/protocol.rs` instead of duplicating raw string literals across modules.
- **CLI presentation transforms vs. IPC wire preservation**: When CLI subcommands format IPC responses (such as `bpmute status --json`), apply CLI-requested aliases or JSON shape adaptations in the command output handler (`src/cli/commands/`) rather than polluting authoritative daemon IPC structs (`DaemonStatus`) with redundant alias fields.
- **Domain vocabulary (`GLOSSARY.md`)**: Use `Wearable`, `Enrollment`, `Signal Lost`, `Epoch`, `Quiet-Wake Baseline`, `Calibration Maturity`, `Monitoring Session`, `Anomalous Session`, `Grace Period`, `Activity Hold`, `Sleep Action Pipeline`, `Snooze`, `Active Hours`, `Calibration Boundary`, and `Ledger Bundle` across code, comments, tests, and user-facing strings (normalizing colloquial issue-spec synonyms such as `archive` or `dump` to `GLOSSARY.md` terms); keep BlueZ wire identifiers (`Device1`) confined to the BlueZ proxy layer (dummy advertised-name or user-alias literals in tests are exempt, while new test identifiers/assertions should follow `GLOSSARY.md`).
- **Side-effect-free state probes**: Query and condition check methods must be strictly pure and free of side effects. Never invoke an action or mutation method (e.g. `pause_mpris_players`) to probe state; use dedicated inspect/query methods (e.g. `has_playing_players`).
- **Dry-run isolation**: Features executing under `dry_run == true` (such as `--dry-run` or `bpmute test-trigger`) must remain strictly isolated: no OS side effects, zero calibration updates, zero persistence writes, and zero false-positive penalties.
- **External edit isolation**: External file mutations (`$EDITOR` on `config.toml`, external SQLite file imports) must never clobber active runtime or in-memory state until validation passes. On validation failure, render the error prominently while keeping the active valid state intact.
- **Modal state encapsulation**: Avoid bundling unbounded modal text-input logic into monolithic dispatchers; group text input state and validation logic within the modal struct to avoid primitive obsession and unbounded switch growth in input routers.
- **D-Bus & external wire contract verification**: When authoring or mocking `zbus` D-Bus proxies/interfaces or Wayland protocol clients/servers, verify exact method/request names, request opcodes, parameter types, `#[zbus(property, name = "...")]` casing (`UUIDs`, `UUID`), bound interface versions, and object timer/event lifecycle semantics against primary sources (`docs/research/`, `busctl introspect`, or `wayland-protocols` XML), and log or propagate registration, discovery, and subscription errors rather than discarding them.
- **Daemon-to-TUI push and mutation completeness**: Any daemon runtime state rendered in the TUI (such as `wearable_statuses`, `wearable_batteries`, or `alerts`) must emit a control push event on state changes; fields mirrored on both `DaemonStatus` and `Config` (such as `schedule`) must stay symmetrically synchronized across `apply_daemon_status` and `IpcEvent::ConfigLoaded`; initial `Snapshot` hydration must be order-independent with follow-up RPC refreshes (`wearable.list`, `daemon.status`) and gate live telemetry fields (`latest_bpm`, `contact_ok`, chart `window_end_ms`) on both wearable connection status and sample freshness relative to `server_now_ms`; and every TUI mutating command (`TuiCommand` modal/action) plus `OpCompleted` error/success feedback handling must have a real-socket `TuiIpcBridge` roundtrip test in `tests/tui*_e2e.rs`.
- **TUI async detail correlation & error propagation**: Clear stale detail state immediately when switching a master-list selection; apply incoming async detail payloads (`SessionDetailLoaded`) only when the payload ID matches the currently selected row (and ignore them when the list is empty); reload detail on slim push updates (`SessionClosed`) whenever cached child records are fewer than authoritative summary counts; and surface multi-step `TuiIpcBridge` RPC or decode failures via `IpcEvent::OpCompleted` rather than returning silently.
- **Bounded IPC payloads & online/offline pagination parity**: Keep every IPC response and push event containing session-duration-proportional collections (`epochs`, raw samples) well below `MAX_FRAME_BYTES` (`1 MiB`, ADR-0002) via bounded pagination (`EpochPaginator`) or slim metadata-only queries (`*_slim_and_recompute`), backed by realistic long-session tests (`>= 2,500` epochs / `> 1 MiB` uncompressed). Pair any server-side page cap with matching client pagination so online CLI output stays identical to offline SQLite reads.
- **TUI mutation dispatch purity & keybinding isolation**: Action handlers returning mutating `TuiCommand`s (e.g. `SessionEnd`, `WearablesUnenroll`, `OpenPausePopover`) must never mutate authoritative daemon-owned state optimistically; all state transitions and outcome feedback (`op_feedback`) must flow strictly through incoming IPC events (`StateChanged`, `SessionClosed`, `OpCompleted`). Global actions exposed across tabs (such as uppercase `'E'` for session termination) must enforce strict casing separation from contextual tab actions (such as lowercase `'e'` for enrollment on Dashboard/Wearables) to prevent unintended trigger overlap.
- **Tri-state patch completeness (`PatchField`)**: Tri-state mutation forms and command boundaries (`TuiCommand`, CLI mutation handlers) pass `PatchField<T>` (`Set` / `Clear` / `Unchanged`) directly per field rather than flattening into `Option<T>` + a global `clear: bool`, keeping hidden or read-only fields `PatchField::Unchanged` and explicitly clearing emptied editable fields with `PatchField::Clear`.
- **TUI toggle and dynamic target clarity**: Boolean switches in TUI modals must state what both enabled and disabled states do (e.g. window-only vs `24/7`) alongside their keybind hint, and time-targeted actions (e.g. `until-morning` pause) must render the resolved `HH:MM` target rather than opaque phrasing.
- **Unified TUI action placement**: Tab views, chart legends, and inspect readouts must never render internal secondary action/shortcut bars (such as `[←/→] Scrub` or `[Esc] Exit`) if those actions are already exposed and dispatched via the global footer bar (e.g. `[1-4] Tabs`, `footer.rs`). All tab navigation and global/mode shortcut hints belong in the footer to preserve viewport real estate (especially within the `42–44` column `80x24` History detail pane) and ensure visual consistency across tabs.
- **Single source of truth for enumerated UI items**: Share one enum (such as `CorePreference`) across view rendering and input dispatch rather than duplicating parallel arrays and numeric indices.
- **`--ascii` and `NO_COLOR` glyph parity**: Branch every Unicode glyph (borders, arrows, warning icons such as `" ⚠ "` vs `" ! "`) on `app.theme.ascii`, and verify error/populated states at `80x24` and `60x18`.
